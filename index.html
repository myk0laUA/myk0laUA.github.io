01 — SOLO CLIENT PROJECT / APPLIED AI

Making sense of
financial news.

Took a startup founder’s brief from prototype to an Azure demo as the sole developer. Built a pipeline that turns financial news into validated corporate-event records across 20 categories, with cost controls around every paid model call.

  • Python
  • Mistral 24B
  • Azure
  • PostgreSQL
Inside the project +

Ownership: Sole developer for a startup founder’s MVP brief. Designed and implemented ingestion, candidate selection, structured extraction, evaluation, deployment, and operational documentation.

Architecture: Dataset, URL-list, and RSS inputs flow through fetching, cleaning, and deterministic candidate selection before reaching the LLM. Articles with no event candidates skip the model entirely. Outputs pass schema validation and export checks before becoming graph-ready records.

Model tradeoff: Chose Mistral Small 3.2 24B through OpenRouter. In my project-specific comparisons, it met the extraction goal at lower cost and produced fewer unsupported extractions than the alternatives I tried. The decision favored measured task performance over general model capability; validation and hard spending caps remained necessary.

Cloud delivery: Deployed and demonstrated the MVP in an Azure development environment using Container Apps Jobs, Service Bus, Blob Storage, PostgreSQL-backed idempotency, and Key Vault. Added offline tests, capped live canaries, audit records, and a configurable fallback path.

Evaluation: Across 2,936 articles, the pipeline produced 1,332 records, with 1,328 passing schema validation. Schema validity measures output structure, not factual accuracy.

On a 300-article holdout, improved candidate precision from 45.0% to 58.6% at approximately 95% recall. Caching and selective invocation reduced model calls by 17.6% and token usage by 17.9%.

On a separate 200-article rare-event benchmark, improved candidate recall from 75.7% to 87.1%.

Scope: A demonstrated client MVP, with further production hardening identified for crashed-worker recovery, alerting, and retention. Client source code and internal documentation are private.

03 — MACHINE LEARNING / CLASSIFICATION

From survey to prediction

Built a reproducible training and prediction pipeline for messy survey data. Compared Random Forest and neural-network models, then packaged preprocessing and the trained model together for command-line inference.

  • PyTorch
  • scikit-learn
  • Pandas
Inside the project +

My role: Machine Learning Engineer · University of Toronto, CSC311.

Prepared 1,644 survey rows from 548 respondents using imputation, categorical encoding, and text features. The PyTorch pipeline splits by respondent and fits preprocessing on training data only.

The neural network achieved 89.96% accuracy and 0.900 weighted F1 on 249 held-out rows. Training and inference include early stopping, model serialization, input validation, and a prediction CLI.
